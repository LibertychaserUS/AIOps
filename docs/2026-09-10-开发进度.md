写进 [`pr-brief.md`](pr-brief.md)、[`2026-09-10-对话整理.md`](2026-09-10-对话整理.md) §11、`forge submit`（base 必须是 `protect`，默认 `main`）、`sop-lock`。

一句话：

> 要进 `main` 的 PR，必须是整段工作的封顶。合完立刻以 `main` 上那颗新 SHA 为底再开下一枝。不要从即将被压掉的旧头再叠。

| 锁 | 意思 |
|---|---|
| 封顶 | 一单 PR = 整段工作。squash 之后 `main` 只多一颗，标题就是那颗 Conventional Commits header |
| 换底 | 下一枝从新的 `main` SHA 开 |
| 不叠旧头 | 禁止把未合 / 即将 squash 的 `cursor/…` 当下一单的 base |

对照（不是本仓 RFC）：Conventional Commits FAQ 允许 squash；GitHub：squash = one logical change，合完不要在同一 head 续开 PR；仓设置可用 PR 标题当 squash subject；Graphite restack = 底被 squash 后换到新 trunk。出处表在 `pr-brief.md`。

不接 Graphite stack / merge-when-ready。Forge 仍不合入。#5 合完后，**不要**再以 `cursor/fix-release-6842` 为底开 #6。

```text
gh repo view LibertychaserUS/AIOps --json isPrivate,url,visibility
→ {"isPrivate":true,"url":"https://github.com/LibertychaserUS/AIOps","visibility":"PRIVATE"}
```

尝试：

```text
gh repo edit LibertychaserUS/AIOps --visibility public --accept-visibility-change-consequences
→ HTTP 403: Resource not accessible by integration
   https://api.github.com/repos/LibertychaserUS/AIOps
```

REST 再试：

```text
gh api -X PATCH repos/LibertychaserUS/AIOps -f visibility=public -f private=false
→ {"message":"Resource not accessible by integration",
   "documentation_url":"https://docs.github.com/rest/repos/repos#update-a-repository",
   "status":"403"}
```

同时读到的权限块：`permissions.admin=false`（maintain/push/pull/triage 在该响应里也是 false）。  
`gh auth status`：当前身份是 GitHub App 账号 `cursor`（installation token），**不是**仓库所有者 `LibertychaserUS`。App 没有 Administration，改不了 visibility。

GitHub MCP（`get_me` = `LibertychaserUS`）没有「改仓库可见性」的 tool。对这个私仓的 PR / release 读接口返回 **404**，用不上所有者 OAuth 来 PATCH。环境里没有 `GH_TOKEN` / `GITHUB_TOKEN` / `FORGE_SUBMIT_TOKEN` 可换一把有 admin 的 PAT。

**结论：仓库现在仍是 PRIVATE。不是「已经改成 public」。**  
要真正公开：所有者在 GitHub UI（Settings → Change repository visibility → Public），或用带 `Administration: write` / 经典 `repo` 的 PAT 再跑上面的 `gh repo edit`。
